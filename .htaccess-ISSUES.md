## Critical Issues Identified

### 1. Content Security Policy (CSP) Conflicts

**Location:** Lines 110-128 (Headers Security Advanced & HSTS WP 5.1.6)

**Problem:** The Content-Security-Policy header has conflicting configurations:

**Current `.htaccess` (Line 114):**
```apache
Header set Content-Security-Policy "default-src 'self' https:; script-src 'self' 'unsafe-inline' 'unsafe-eval' https: data:; script-src-elem 'self' 'unsafe-inline' https: data:; worker-src 'self' blob:; style-src 'self' 'unsafe-inline' https:; img-src 'self' data: https:; font-src 'self' data: https:; connect-src 'self' https: wss:; frame-src 'self' https:; object-src 'none'; base-uri 'self'; form-action 'self'; upgrade-insecure-requests"
```

**Restored `.htaccess` (Line 114):**
```apache
Header set Content-Security-Policy "default-src 'self'; script-src 'self' 'unsafe-inline' 'unsafe-eval'; style-src 'self' 'unsafe-inline'; img-src 'self' data: https:; font-src 'self' data:; object-src 'none'; base-uri 'self'; form-action 'self'; upgrade-insecure-requests"
```

**Impact:**
- May block legitimate resources from external domains (CDNs, fonts, APIs)
- Could prevent WooCommerce payment gateways from loading
- May block AJAX requests needed for dynamic content
- Could prevent third-party widgets/embeds from functioning

### 2. Duplicate RewriteEngine Directives

**Location:** Multiple locations
- Line 4: `RewriteEngine on` (LiteSpeed cache)
- Line 68: `RewriteEngine On` (HTTPS redirect)
- Line 78: `RewriteEngine On` (WordPress permalinks)

**Impact:**
- While this typically doesn't cause errors, it's redundant and can cause confusion
- The order of execution matters for rewrite rules

### 3. HTTPS Redirect Configuration

**Location:** Lines 68-72

```apache
RewriteEngine On
RewriteCond %{HTTPS} !=on
RewriteRule ^(.*)$ https://%{HTTP_HOST}%{REQUEST_URI} [L,R=301]
Header unset X-Powered-By
# RewriteRule ^(.*)$ https://%{HTTP_HOST}%{REQUEST_URI} [L,R=301,NE]
```

**Issues:**
- Commented-out redirect rule suggests previous troubleshooting
- The `Header unset X-Powered-By` might not work if mod_headers isn't loaded before this point

### 4. WordPress Rewrite Rules Order

**Location:** Lines 77-85

The WordPress rewrite rules come after the HTTPS redirect, which is correct. However, the rewrite conditions might conflict with other rules.

**Potential Impact:**
- Permalinks may not work correctly
- Custom post types might fail
- REST API endpoints might be blocked

### 5. Wordfence WAF Path

**Location:** Lines 90-95

```apache
php_value auto_prepend_file '/home/netdevsne/mariasplace.com/wordfence-waf.php'
```

**Potential Issue:**
- Hardcoded absolute path may not match current server configuration
- If the path is incorrect, Wordfence won't load and site may break

### 6. Multiple Security Headers

**Location:** Lines 110-128

Multiple overlapping security headers:
- Content-Security-Policy
- Cross-Origin-Embedder-Policy
- Cross-Origin-Opener-Policy
- Cross-Origin-Resource-Policy
- Permissions-Policy
- X-Content-Type-Options
- X-Frame-Options
- X-Permitted-Cross-Domain-Policies
- Strict-Transport-Security

**Impact:**
- Too many restrictive headers can break legitimate functionality
- Third-party integrations (payment gateways, social media embeds, analytics) may be blocked
- WordPress admin AJAX requests might fail

## Recommended Actions

### Immediate Testing:

1. **Temporarily rename .htaccess:**
   ```bash
   mv .htaccess .htaccess.disabled
   ```
   Test if site functionality improves. If it does, the .htaccess is definitely the issue.

2. **Test with minimal .htaccess:**
   Keep only WordPress rewrite rules and HTTPS redirect, remove all security headers temporarily.

3. **Gradually re-enable features:**
   Add back headers one at a time to identify which one(s) cause issues.

### Long-term Solutions:

1. **Review Content-Security-Policy:**
   - Allow necessary external domains
   - Add exceptions for WooCommerce payment gateways
   - Configure for WordPress AJAX endpoints

2. **Verify Wordfence path:**
   - Confirm the path `/home/netdevsne/mariasplace.com/wordfence-waf.php` exists
   - Update if server structure has changed

3. **Optimize header configuration:**
   - Remove duplicate or conflicting headers
   - Use WordPress filters where possible instead of .htaccess

4. **Test in staging:**
   - Never modify .htaccess directly on live site
   - Test all functionality after changes
